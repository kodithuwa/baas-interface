## Responsive Behaviour

### Available references

- Desktop: `docs/ui/dashboard/desktop.png`
- Tablet: Not provided
- Mobile: Not provided

### Requirements

- Treat the desktop screenshot as the authoritative visual reference.
- Reproduce the desktop layout as closely as possible.
- Do not invent tablet or mobile designs that are not present in the reference.
- Inspect the existing project for responsive layout conventions and reusable components.
- Propose suitable tablet and mobile adaptations based on the desktop layout.
- Preserve content hierarchy, usability, and functionality at smaller screen sizes.
- Avoid horizontal scrolling unless explicitly required by the design.

### Responsive assumptions

The implementation plan must describe:

- How the sidebar behaves on tablet and mobile.
- How multi-column layouts adapt to narrower screens.
- How cards, tables, and other content reflow.
- Any navigation changes required for smaller screens.

These are proposed adaptations, not screenshot-matching requirements.
